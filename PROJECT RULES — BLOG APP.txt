PROJECT RULES — BLOG APP
(Frontend + Backend)

This file defines non-negotiable rules that must be followed while working on this project.
Any future developer or assistant must read and follow this before making changes.

--------------------------------------------------
1. FILE HANDLING & CODE UPDATE RULES
--------------------------------------------------

- Before rewriting any file, ASK if the file exists.
- If the file exists, the user will provide it.
- Update the code without removing existing functionality unless explicitly instructed.
- Any code change MUST be delivered as a FULL FILE rewrite.
- Partial snippets, patches, or diffs are NOT allowed.

--------------------------------------------------
2. EXPLANATION & COMMUNICATION RULES
--------------------------------------------------

- Keep explanations brief and to the point.
- Focus on building the project, not explaining concepts.
- Ask once if something is unclear — do NOT assume.
- Warn before making any change that may break functionality.
- Highlight conflicts with existing rules before proceeding.

--------------------------------------------------
3. SOURCE OF TRUTH & AUTHORITY
--------------------------------------------------

Priority order (highest to lowest):

1. Task File
2. This Rules File
3. Existing Code
4. Suggestions

- Never redesign flows or architecture unless explicitly instructed.
- Never assume behavior — always verify.

--------------------------------------------------
4. BACKEND RULES (Django / DRF)
--------------------------------------------------

- Backend must be tested in Postman first.
- Frontend work starts only after backend APIs are verified.
- Django must remain modular and app-based.

File separation is mandatory:
- models.py
- serializers.py
- views.py
- urls.py

- No logic inside urls.py.
- Authentication uses JWT for protected APIs.
- Admin access is based on:
  is_admin OR is_staff OR is_superuser
- Notifications should be created via signals (preferred).
- Payments follow: create → verify → consume (single-use).

--------------------------------------------------
5. FRONTEND RULES (Expo / React Native)
--------------------------------------------------

- Uses Expo Go.
- File-based routing (Expo Router) is authoritative.
- If a file changes → rewrite the ENTIRE file.
- No unused or duplicate imports.
- Pull-to-refresh must exist on all screens except auth screens.
- App name must always display:
  "TRILOK BLOGAPP"
- Do NOT hardcode navigation paths.

--------------------------------------------------
6. AUTHENTICATION RULES
--------------------------------------------------

- Facebook login is OPTIONAL.
- Google login is OPTIONAL.
- Backend social auth endpoint:
  POST /auth/social/
- Frontend must store ONLY backend JWT tokens.
- Social access tokens must NOT be stored on frontend.

--------------------------------------------------
7. NETWORKING & ENVIRONMENT RULES
--------------------------------------------------

- Frontend must NEVER call localhost.
- Always use Cloudflare Tunnel URL.
- Backend, Cloudflare tunnel, and frontend must run together.
- All secrets and configuration must come from .env.
- Never hardcode API keys or tokens.

--------------------------------------------------
8. STANDARD EXECUTION COMMANDS
--------------------------------------------------

Backend:
cd backend
python manage.py runserver 0.0.0.0:8000

Cloudflare:
cloudflared tunnel --url http://localhost:8000

Frontend:
npx expo start --tunnel

--------------------------------------------------
9. OUTPUT & CHANGE CONTROL
--------------------------------------------------

- User decides:
  - What to fix
  - When to fix
  - Order of fixes
- No unsolicited refactors.
- Every change must state:
  - What changed
  - Why it changed
  - Impact (backend / frontend)

--------------------------------------------------
10. FINAL NON-NEGOTIABLE RULE
--------------------------------------------------

If something is unclear:
STOP and ASK.

Never guess and implement.

This file overrides assumptions and assistant preferences.
